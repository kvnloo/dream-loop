# Owner checkpoints and preferences

- Write per-project PREFERENCES before delegating: style reading, nonnegotiable identity, permitted assets/image services, privacy, no-paint-over or no-projection policies, viewer, cadence, budgets and who can promote. Do not carry a prior project's preferences into a new product as universal defaults.
- Show a checkpoint after EVERY lane batch, before another batch. Open the actual media in the owner's chosen viewer with available browser/desktop tools, verify the exact image/page loaded, and report where it is visible. If no display channel is available, provide artifact links and say opening is unverified; a successful launch command is not visual delivery.
- Present TARGET | previous selected | candidate, native crops of worked regions and an honest status: experiment, working preview, kept, owner-approved or shipped. CURRENT may select an owner-requested preview without granting release approval; retain a separate approval field.
- Ask concrete decisions, not “thoughts?”: which shape family, which material read, which protected difference, which of two directions. Ask how the owner reads an ambiguous style before launching a material lane.
- Freeze “pretty close” as an immutable fixture immediately, with source/settings/scripts, locks and hashes. Later lanes work on copies. Owner corrections override stale brief rows; version the decision and re-steer running workers in the same batch.
- If two focused trials preserve the same defect, stop before a third. Show both failures, explain the tested mechanism and offer genuinely different representations/techniques with costs and risks. An extra parameter variant or a renamed lane does not reset the stop rule.
- An AI HOLD does not veto an owner checkpoint or approved aesthetic choice. Keep technical failure, brief shortfall and owner acceptance separate. Never silently promote a working preview because judges prefer it.
- Recover specific features the owner liked from rejected history onto the current lineage. When they prefer older shapes and newer variation, build that combination explicitly; compare against both sources, not merely the last candidate.
- For small explicit direct edits, use the simplest bounded edit and isolation preview rather than a long delegated competition. For “diagnose, don't change,” inspect and stop. If constraints conflict, show isolation/wireframe/ray evidence and ask rather than deforming protected parts.
- An owner annotation is evidence with uncertainty. Verify registration from image features, preserve visible faces, and separate registration residual from hand-drawn ambiguity. Ask for a flattened export when marks are missing; do not invent them.
