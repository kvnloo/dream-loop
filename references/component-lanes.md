# Brief-driven component lanes

Switch from whole-frame nibbling when recurring material/form gaps survive paired preference wins. Write per-element COPY/INTENT rows from native crops and the owner's ART STYLE interpretation, not adjectives alone.

## Diagnose before dispatch

Classify FORM (silhouette, relief, coverage, boundary), MATERIAL RESPONSE (optical layering, roughness, transmission), LIGHT (source, visibility, reflection environment), ALBEDO (color/print), with MAPPING and DISPLAY as explicit confounds. A shader count does not prove visible relief, and a dark low-roughness surface may simply have nothing bright to reflect. Probe actual receiver/material bindings and occlusion before touching a guessed knob.

## Freeze common context first

Integrate exposure/lighting restoration BEFORE other lanes develop. Freeze camera, view transform/look, exposure, lights/world, bounce limits, clamps, masks and shared postprocessing. Isolation means owned component/namespace, not a different lighting universe. Preserve enough context geometry for contact, reflection and occlusion. Compare neutral coupons too when diagnosing a mechanism, but approve in the real fixture.

## Contract and sequence

1. Give each lane a copy, explicit read/write roots, one hypothesis, protected assets, exact version paths and a budget. Use [lane brief](../templates/lane-brief.md). Require RESEARCH-NOTES before implementation when cause is unknown.
2. Complete the [exemplar/style gate and preflight](exemplar-and-preflight.md): native crop, structural reading, two distinct form hypotheses, negative example, real coupon, owner approval. Approve one exemplar at final pixel scale before scattering, instancing or applying across all faces. Shape family and coverage precede material response, then fine detail. More hairs or droplets cannot repair the wrong envelope.
3. Require an idempotent apply operation, component/source artifact, complete dependencies, source/fixture hashes, control and candidate captures, native interface crops, guard receipts, limitations and READY only when the contract is actually complete. READY means deliverable available, not owner approval.
4. Inventory inherited contributors to the affected region, including unowned lights, hidden geometry, object-linked material overrides and stale shader branches. Request ownership changes for confusing legacy contributions; don't weaken guards to delete them silently.
5. Integrate through one fixed-order driver: baseline lighting/exposure → materials → geometry/props/relief → dependent effects/attachments → one global bloom/postprocess owner. Freeze selected scripts/assets before applying. Choose one owner per surface/effect; never stack duplicate top systems, dew or serial glare.
6. Rebuild from the frozen base unless a separately audited incremental mode is declared. Reapply twice and save/reopen to test idempotence. Re-seat dependent geometry against actual evaluated surfaces; counts alone cannot establish contact or clearance.
7. Verify protected state and measured protected-pixel deltas; unchanged shader constants do not guarantee unchanged appearance after a lighting change. Identity is not bit-identical GPU rendering. Retain judged and replay captures separately.
8. Review full hierarchy and interfaces (prop/support, growth/labels, relief/foliage, emitters/postprocess). Compare the integrated component to its exact selected source crop; a new hybrid has not beaten both alternatives merely because it is newest. Then checkpoint with the owner.

Use [integrate skeleton](../templates/integrate.py) as an adapter protocol, not a universal renderer. Domain code must supply build/save/reopen/render/guard operations and real evidence. Domain-specific craft lives in [domain packs](domain-packs.md).
