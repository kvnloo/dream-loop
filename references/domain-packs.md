# Domain packs: keep craft separate from loop policy

Dream-loop owns target/brief, evidence, critic/owner protocol, lineage and promotion. Domain packs own rendering/modeling/interaction mechanisms and must honor that contract. They may add technical checks, not silently replace owner intent or acceptance policy.

## Blender

Load installed `blender-reference-match-loop` for camera/edge consistency, object-local edits, render-visible ray probes, projection/UV separation, direct mesh isolation, material ownership and sibling transplants. Load `blender-lookdev-recipes` for HDR core/sheath/halo, refracting cornea, wet reflection/dew, bioluminescence, clear coat, pigment/tangent detail, moss/ivy, single bloom/exposure and camera projection. Numeric recipe values are coupon starting points, not universal constants.

Keep project object names, exact source paths, image dimensions, owner theme preferences and frozen geometry in that project's case study. Preserve old specialist source files before restructuring so detailed craft and negative results are not lost. Old advice to warp box tops conflicts with a later flat-top lock: use the current owner constraint, and keep the older approach as a rejected/conditional technique rather than a universal rule.

For generated targets/material proposals, load `chatgpt-image-generation` when installed. Verify live access/size instead of promising API dimensions; retain originals, prompts and hashes. Its local adapter paths are environment discovery inputs, not portable dependencies of this pack.

## Three.js / games

Lock camera plus simulation time/seed, viewport/DPR, tone mapping/exposure, lighting and asset readiness. Use graybox/massing before shaders. Isolate the component in the actual renderer; freeze shared postprocessing. Check real GPU backend, console/errors, interactions, frame pacing and device memory in addition to the hero screenshot. Fixed-view projection cannot silently replace a rotatable asset. Treat animation/alternate cameras as additional held-out capture states.

## UI / web products

Lock viewport/state/content/fonts and screenshot density. Translate composition into hierarchy/layout, visual surface into type/color/texture, details into spacing/icon treatment; version this rubric mapping. Keep semantic HTML, accessibility, responsive behavior and real-device input/performance as independent technical gates. Critique scene art and DOM chrome separately, then check their integration. An editor should operate on the user's real artifact unless a separate surface is explicitly requested.

## Existing optional helpers

Retain `polyhaven_pbr.py`, Fal batch generation, preview server, overlay, crop and structure gates. External asset/service choices depend on owner authorization/privacy/licensing, not a fixed model hierarchy. [Legacy 3D lessons](3d-what-works.md) and [creative sources](creative-3d.md) preserve provenance; their old model rankings and universal material assumptions are historical, not current benchmarks.
