# Dream-loop field pitfalls

Lessons recorded by sessions after the v2 rewrite (Oct 16 - Nov 16, 2026), moved out of SKILL.md so it stays under the 8-14 KB authoring target. Each keeps its "Why:" where one was given.

- Do not build from an eyeballed read of a dark or low-contrast region ("needs more sheen", "needs darker moss"): measure the region's low-pass luminance, hue and contrast against the target first. A confident visual read can point the wrong way. In dark scenes, compute colour statistics only on pixels above a luminance floor; raw chroma medians are dominated by near-black pixels and can call a saturated target "less colourful".
- Measure placement and proportion in code, not with vision: in a scene you render, project the subject's anchor points (bones, bbox corners) to screen % after any lens/post warp and fit camera params to the target's numbers. Vision's size and ratio estimates swing between rounds and cannot steer a camera. When the subject's identity intentionally differs from the target (a different person or brand), tell the judge to score style, not identity, or every round loses on design it is not allowed to copy.
- In an unattended image-ideation loop, treat a critic call with no parsed verdict as NOT done. Retry it with backoff, have resume re-ask null-verdict rows (latest row per pair/layer/order wins), and pause the loop (for example with a CriticDown backoff) instead of closing the round as blocked. Ping the critic model BEFORE rendering candidates. If transient failures are counted as done, every later round renders 3 images and gets no signal. Store each failed call's stderr tail in its verdict row. A critic that exits rc=1 within about a second under the loop's service, yet works from your shell, has an environment or credential fault, not a quota problem. Reproduce it under the unit's own env (terminal-agent-orchestration rule 13), then pin what the unit lacks, such as HERMES_HOME. When a code lane is building specific states, weight the ideation rotation toward those states, so its concepts feed the build next; break least-recently-run ties toward states the owner named, not randomly.
- When you add a text ban (placeholder words etc.), run it on every past round's prompts before trusting it. If it returns zero hits while critics keep flagging that text, the check is broken, not clean: real briefs quote HUD text with single quotes ('GOD'S EYE VIEW' included). Apply the ban to every state, not only planning states. Treat a bare dash value ('HOMES EST · —') as a placeholder too. State the rule in the planner prompt as well, so the validator's one re-ask isn't spent on it.
- Bind every cached verdict and composite to the exact pixels it judged. Store the (parent, candidate) image sha256 in each critic row, and count a row as done only while both shas still match the files on disk. Otherwise a resumed or re-composed round reuses a verdict on images the critic never saw. Rebuild a code-composited candidate whenever it is older than its scene render or the HUD/spec code that draws it (`hud.stale(out, *deps)`); a HUD fix otherwise ships under an old composite.
- Check the spec's countable facts in the render, not just stray text. A vision call counts each one (storeys, at ±1), caches the answer per candidate, and a mismatch makes the accept CONTRADICT and parks the round. Critics accept a 6-storey render for a 3-storey spec, because nothing compares them. After adding the check, backfill it over past accepts and report the lower coverage honestly.
- When the loop logs critic-down, ping each critic model from your shell with a timer (`hermes chat --oneshot -Q --provider <p> -m <model> -q 'Reply with the word ok'`) and check load/PSI before touching the service. If one model answers in seconds while the host load is falling, the pings were starved by host thrash and the loop's own backoff resumes; leave it alone. "Gateway draining: update_paused" (visible only uncaptured, on the TTY) means a Hermes update holds the install fence for possibly hours, not quota. Route every critic, ping and vision call through one seam (`llm.run(model, prompt, image=None, timeout, reasoning)`). On any non-zero Hermes exit, it retries the same model once via `claude -p --model <m> --tools Read --permission-mode dontAsk --no-session-persistence`, with the image path in the prompt. Captured drain refusals are rc=1 with empty output, so string-matching never fires. Test with fake binaries on PATH, then live on a stored render. Only a model that fails fast from the unit's env is a credential or env fault.
- When candidates show numbers (planning, traffic, zoning, data HUDs), gate them in code twice; critics cannot check arithmetic from pixels and will accept clutter they themselves flag. (1) Spec-before-render: each direction carries a numeric spec (sourced numbers, a before -> after delta, a stated cost, a listed control set within budget, street sections summing to the right-of-way, FAR/shadow/coverage arithmetic, VARIANCE labels); a deterministic validator re-asks once, then drops failing directions before any render, and the render brief may show only the spec's display strings. (2) Render check before a winner can become a parent: a vision call transcribes the readouts and counts the tool's controls (host chrome excluded); garbled or invented figures, clear control excess, or a failed transcription park the candidate, because image models garble digits even when handed the exact string. Calibrate the control counter on the owner-approved image first. Also require at least 2 cross-domain effects (one computed that code re-derives), and for building-side states (shadow, growth, massing) one of them street-side (street, transit, parking or walk), because task critics score planning depth low when every effect stays on the building, and one shared scenario file that every state's numbers must agree with, and log a coverage/depth exit metric each round. Before validating, fold fields the model put beside the spec into the spec. When a check looks for a computed figure inside a display string, extract signed numbers and normalise the Unicode minus (U+2212); an unsigned number regex reads '-2 m' as 2 and rejects a correct negative gap or delta. Treat a spec-reject whose message quotes the very value the display shows as a validator bug: add a test from that round's raw reply first. If you skip this, the round dies as a false reject twice over. Replay a spec-invalid round's saved raw replies before changing rules. Contract, rule table, scenario, effects, audit and calibration steps: [planning specs](planning-specs.md). When the critic ties or parks a candidate because a still image cannot prove a constraint (that the geometry obeys the stated FAR, height or setback, or that a toggle really changes the numbers), stop re-dreaming that state. Hand the accepted spec to the code lane, where the geometry is computed from the numbers and asserted by tests, because no further image round can supply that proof.
- When planning screens keep failing on numbers or clutter, stop asking the image model to draw the HUD. Have it render the 3D scene only: refuse briefs that quote on-screen text or control labels in code, and composite the product's HUD from the validated spec in code, using the product's own CSS palette and fonts. Readouts and control counts are then right by construction. The render check becomes "no stray text or UI in the scene layer" instead of transcribing digits. Never drop a label that doesn't fit, and draw every control at the changed target with the product's own in-world control (such as its plot wheel), keeping the side panel for readouts only, and drop the panel once critics still call it detached: put at most 2 callouts at the target (the headline is the first before->after change, not the parcel or ROW size), put every other figure in a bottom consequences ticker, and round estimates in one display() function (raw values stay in the spec for every check). Frame the header by the plan's scope: a block/district plan shows its plot count and total area, never the anchor plot's id and area, or a district footprint (24k m²) sits beside a 1,600 m² plot and reads as impossible. Strip the model's own tab or label prefixes ('AI CONCEPT:') from any cost or ticker line it writes. Keep the wheel off the changed object with a vision-located keep box (outline plus massing, shadow and lane change). Colour masks misfire on sky and water. Hug that box's perimeter, because a full ring sized to clear the box floats away; tether BUILD to it. Add a read-only resource bar whose numbers come only from a replay of the accepted chain_from chain through one ASSUMED goal table (score clamped to [-1,1], with no score when a required metric is unknown). A spec's stated before wins over the assumed base, because a plot-scale base applied to a district gives nonsense like HOMES 12->600. Write an equal pair as one value marked UNCHANGED, so a carried loss stays visible without looking like a change. Read structured calcs (e.g. a parking calc's spaces) and skip numbers marked ASSUMED, which are inputs, not outcomes. Otherwise an accepted move can silently add nothing to the score. Export the replay as a golden fixture for the product's own port of the score. Test it all on stored scenes before new rounds ([code-drawn HUD](planning-specs.md#code-drawn-hud-scene-only-renders)). Count the control budget as actionable targets, not containers (a draggable multi-part control is typed {label, targets:n}). Cap each critic stage at about 3x its measured healthy p95, not one hour. Add a host-pressure gate before each round, and a circuit breaker: two consecutive same non-accepts on a state drop it from rotation until a replay shows a fix. Measure depth as a linked chain of accepts (spec.chain_from), with each panel's 'before' equal to the previous panel's value, not as accepts in N unrelated states.
- Before tripping a circuit breaker or calling a state stuck, check whether every rejected candidate lost on the same code-drawn layer (HUD text size, ticker, composite) while beating the parent on the task. That is one shared rendering bug, not bad ideas: fix the layer, redraw and re-judge those rounds from cached scene renders (zero new renders), then clear the breaker. First diff every HUD surface that shows the same metric (resource bar vs ticker vs callout), because critics punish a self-contradicting HUD on layout and text. All surfaces must share one rounding function, one EST/UNCHANGED label convention, and one source. A stated before->after in the spec suppresses any derived chip for the same quantity (a curb calc's "spaces removed" beside a stated PARKING 4->1 reads as two different answers). Pin this with a test that replays the losing round's spec and asserts the chip strings, then restart at the round boundary. Also pin scene parameters that must stay fixed across rounds (sun angle, camera) in the spec, since drift between rounds reads as a regression.
- A circuit breaker must release itself when the code it blamed changes (store the compositor code mtime at trip; hold only while that code is unchanged), and the round picker must never fall back to states that already pass or to non-exit states while the exit metric is short: an empty pool stops the loop (`stopped pool-empty`) and the launcher refuses to start unless a `--reachable` check names every needed state as in rotation or covered by a code-lane gate receipt. Why: breakers tripped on a since-removed side panel held three exit states for ten rounds while the fallback spent 12 renders on states that could not move the metric.
- Compute the exit metric in a fresh subprocess, never with `import` inside the long-running loop: Python reuses a module already loaded, so the loop logs a metric from rules that predate today's edits (it logged 3/6 when the on-disk check gave 2/6). Log a correction event; don't rewrite old events.
- A HUD-fault verdict is also a single read: before it holds a state out of rotation, re-judge only the faulted code-drawn layer once on the same pairs (zero renders) and hold only if the fault reproduces. Why: a layout 'parent' 3/3 that re-judged as split/tie 3/3 on the unchanged HUD took the exit out of reach and stopped the loop for 20 minutes. Measure a HUD change on cached scenes (re-compose and re-judge, no renders) before relaunching; re-judge the OLD HUD too, because without that baseline a neutral change reads as a fix. Never claim a critic-measured improvement when both arms score the same; keep the change only for the rule it satisfies by test.
- Every exit state needs a validator rule for its own defining content, not just the generic number rules. Why: a 'growth' accept passed with stages/cohorts null (one 9->12 m height change under a NOW/5 YR/15 YR scrubber); the critics liked it and the metric rose. Growth now needs >=3 timed stages (NOW = before, last = value) and the HUD draws them. When an accept moves the exit metric, read its spec against the state's brief, not only the render.
- Judge brand like-with-like. If a parent's HUD was painted by image generation (a seed, or a round from before compositing) and the candidates' HUD is drawn by code, judge scene against that parent and judge brand against the newest audited code-composited accept, redrawn in the current HUD. Tag each breaker with a judge version (`JUDGE`), and bump it only together with a test that proves the judging changed. A bump releases breakers tripped under the older judge; other loop edits do not. Why: two section rounds won task, layout and text but lost brand alone to a painted-HUD seed. That tripped the breaker, made the exit unreachable, and the launcher correctly refused to restart.
- When a loop gains a new critic sub, stage or state, assert every registry keyed by it (time caps, layer lists) covers what the source calls: grep the source in a test. Why: a stubbed `critic()` let a new `critic-brand` sub pass every test while the live loop died twice on `KeyError` from the missing time cap.
- Pin every shared quantity the validator checks across rounds (sun altitude, park distance, anchor area) in the scenario file, and state each validator rule in the planner schema. Why: the planner re-picked the park distance each round (20/40/26 m) and was never told the crossing rule, so it spent its one re-ask on an unstated rule and the round closed spec-invalid. Missing evidence (no facts file, zero reads) audits UNVERIFIED, never PASS. Render one candidate per distinct plan (same numbers/effects/section is one plan). After a judge change, replay the cached rejected rounds (`--replay rNNN`, 0 renders) before rendering that state again.
- A replay re-closes a round, so every write-once artifact of that close (comparison sheet plus receipt) must be moved aside first (`compare.pre-replay.*`). Why: the replays flipped r058 and r056 to ACCEPT, but the sheet tool refused the reused path, and the board kept showing 'CANDIDATE (reject)'.
- Loop tests must stub the seam the loop really calls and never copy live state files (CURRENT, audit) into a fixture. Why: `exit_metric` shelled out to the live exit check, so a stubbed `exitcheck.main` was dead code and the tests asserted tonight's live 2/6; they broke the moment a replay legitimately moved it to 4/6.
- One model's scene count is a single critic: take three reads (mix models), majority wins, else UNVERIFIED (neither PASS nor CONTRADICT). A shadow move must change whether the shadow reaches the protected edge (before and after lengths on opposite sides of it), or it buys nothing.
- When the loop's code and artifacts live in a non-git directory, snapshot it (tar with a timestamp, or `git init` a local repo) before any lane edits it, so a bad fix can be reverted and diffed.
- The owner's standing rule is that a loop runs until its exit metric is met. Do not park it on an owner "is this enough?" question; Pause only for a fix lane. Verify the fix yourself before resuming:
  - rerun every loop test file;
  - read the re-judged critic rows for the rounds it replayed;
  - vision-check one rebuilt compare sheet (same HUD on parent and candidate, no clipping or placeholders);
  - confirm every code file's mtime predates the restart.
  Then remove the stop-after cap and STOP file and restart through the loop's launcher script. When you edit loop code mid-round, set the stop-after cap to the running round and, in the same step, arm one background job that waits for the unit to go inactive, checks for the `stopped STOP_AFTER <R>` event, moves the cap aside and runs the launcher. Log the relaunch as armed only once that job's id exists; a progress line promising a watcher nobody started leaves the loop stopped all night.
- A scene-count tolerance (e.g. storeys ±1) must never let a render of the unchanged state pass a small change: when the spec has a `before`, a count nearer the before than the after is a contradiction (`count_errors(expected, observed, tol, before=)`). Why: a ±1 storey tolerance lets a render of the untouched building pass a one-storey cut, and the critics accept it. When the spec has no `before`, a ±1 pass cannot tell new floors from existing structure (a frame under construction gets counted too), so vision-check which structure the reads counted before letting the accept move the metric. Vision-check every planning ACCEPT that moves the exit metric before counting it. Demote a false PASS in the progress log and report the lower coverage, rather than keeping the higher number.
- An image-edit model keeps whatever the seed shows, including a translucent planning volume above a roof. So a change that REMOVES height or mass must say so explicitly in the scene prompt: draw the building N floors shorter with a flat roof, and draw no translucent volume, box or wireframe above it. Also state the consequence the change should produce, computed from the spec (for example 'cast shadow about L m long, ending short of the park edge P m away'). Generate these clauses in code from the spec's before and after (`floors_clause`), and test that an addition gets no removal clause. Why: a 'reuse the planning geometry' brief rendered a one-floor cut as the old building with a box on its roof and no shadow, and all three floor reads parked it.
- Once a parked round has a diagnosed cause, stop the next round while it is still planning (no renders on disk yet, so the stop is free), fix the cause with a test, then relaunch. Letting it render the same state repeats a known failure and wastes renders.
- A countable fact the spec states in another unit (height in metres instead of storeys) silently bypasses the scene check: no reads are taken and the audit returns PASS. Make the validator reject a changed height that has no storey count with before → after, and say so in the planner schema. Why: a shadow round promised 'FRONT 12 → 9 m', took zero floor reads, and logged EXIT-MET on a render showing about 6 floors with rooftop boxes still drawn.
- Never trust the loop's own EXIT-MET. Before calling the goal met, open the metric-moving round's files and render: the scene reads must exist, and your own vision read must match the spec. When it fails, retract the exit in the log, and demote CURRENT for that state only while the loop is stopped (the loop rewrites CURRENT.json from the copy it read at round start).
- A resumed round must pass the same pool check as a new one: when the loop restarts mid-round, re-run the pool choice against coverage measured now and shelve (rename aside, files kept, event logged) any open round whose state has left the pool. Record each round's coverage and pool at start (`cov-at-start.json`) and judge 'rendered a non-exit state' against that, not today's coverage. Why: a round opened under a false 6/6 resumed after the demotion and rendered a state that could not move the metric.
- Every quantity that the validator checks against a limit must come from a scenario pin, never from the proposal. Why: the planner set the zoning FAR equal to its own proposal each round, so 'within zoning' could never fail. Pin it as ASSUMED and list it for the owner.
- A growth (or any change) spec must promise a countable that changes (storeys before ≠ after), and an unchanged count gets zero tolerance. Why: a FAR-only growth spec counted 4 → 4 storeys and passed reads 5/4/5 on ±1.
- Floor counts in scene prompts must say the ground floor is included and that a shopfront or podium level is one of those floors, and must forbid rooftop gardens, pavilions and plant rooms on a cut. Why: a 3-storey cut rendered as shop plus 3 floors plus a roof garden and read as 4.
- Loop tests must never reach a live model: stub the single LLM seam to raise and cache any facts files the round reads. Then prove it with a subprocess spy (0 live calls). When you add jobs to a calibration (control sheets), give a stub judge's scripted `iter` answers only to the jobs it was written for (match on the image name). Otherwise threaded new jobs consume the sequence in random order and the test flakes. Why: a later-added scene-facts step made 3 live calls inside an end-to-end test, which failed intermittently wherever the model CLI was off PATH.
- When two rounds lose on brand alone with the same named faults, fix the code-drawn HUD layer, not the ideas, and measure the fix with a 0-render replay before relying on it. Code-drawn HUD uses the app's ONE accent token (no second warm colour, even for cost text); each quantity appears once in the spec's own label; at most one timeline line in the strip; timeline stops (NOW / N YR) are one scrubber rail at the plot, never extra wheel discs. Assert these as pixel/manifest tests.
- A replay re-judges only the round's original best, twice; accept only when both passes agree (split = park). The brand reference moves when a state is accepted, so replays across that boundary are not comparable.
- Test fixtures must pin every state they replay (CURRENT and audit coverage) to its as-of value; a guard test refuses unpinned fixtures, because each live accept otherwise breaks the suite and blocks relaunch.
- Code edits land only on restart: compare the unit's ExecMainStartTimestamp with the file mtimes; restart only before any render, else STOP_AFTER the round.
- Every figure the seed prints for the anchor plot (storeys, homes, jobs) is that plan's baseline: read it three times (mixed models), pin it in the scenario, and make the validator reject any other parcel-scope 'before'. Why: storeys were pinned but homes were not, so a shadow accept drew HOMES 12 → 6 beside a seed printing HOMES 48 and had to be demoted.
- A chain link is picture lineage, not a JSON field: a link counts only when the round's ledger `parent_round` equals its `chain_from` round, and a state with no accept grows from the chain head's accepted picture. Persist the chosen parent per round (`parent.json`) so resume and replay keep it. Why: five rounds claimed `chain_from` while every image parent was a seed; counting them honestly dropped the chain from 2/3 to 1/3.
- Layout code that places HUD around the plot must not treat the plot box as an obstacle when the plot fills the frame (district states): the outline is `used[0]`, so every slot collides and controls fall back over the header. Dock scrubber + actions as one group checked against HUD boxes only (`used[1:]`). Why: r071 lost layout 6/6 to a scrubber floating mid-map and six controls over the subtitle. Reproduce in a test with the round's own keep box (`cand.png.json` outline), not a fresh outline guess.
- Three named directions on one identical plan are a validator error (planspec.dup_plan_errors in the fix pass), not a silent collapse to one render. Why: r068 and r072 (shadow) each became one picture vs the parent and parked.
- Before shipping a new spec-gate rule, replay it over every accepted round's ideas.json and list which rounds it would now reject. Why: the first no-negative-figure rule rejected a counting curb PASS (an area in m²) and ordinary signed deltas; narrowing it to what the critics named (gaps and distances) was only possible because the replay exposed them. Pin the accepted round the first draft would have blocked as a negative case in the rule's test. Narrow the rule (tighten the label regex, exempt the legitimate shape) and pin that accepted case as a passing test. Do not ship it and demote the accept. Hits on rounds already demoted are fine. Rerun the exit check after widening any label regex, too: the audit re-applies spec rules to every accept. A broadened receptor regex once read a section's 'SIDEWALKS 9 → 12 m' width as a receptor distance and CONTRADICTed a PASS.
- Stamp a breaker or hold with the mtime of the code the process loaded at start, never the files' mtime when it trips. Why: r069 tripped after a fix was saved mid-round, the stamp took the fixed file's mtime, and the fix could never release the breaker, which left the exit unreachable.
- The critic's logged `parent` sha is the parent redrawn in the current HUD (`<cand>-hud.png`), not the raw pick. To check lineage, hash that file instead of reporting a mismatch.
- Make the compositor drop repeated figures: ideators write the same figure as a number and an effect, and restate a timeline as a bare `NOW a / 5Y b / 15Y c` row. Remove items equal to a callout, and stage rows whose values match the timeline line. Why: r069 drew YARDS twice on all 3 candidates, which a brand critic reads as a data dump.
- In metric extraction, a stated before → after (an effect arrow, or a number row with `before`) wins over a bare value such as a stage row, and the score measures from that stated base, never from the goal table's assumed base. Why: the stage row 'NOW 24 HOMES' beat the spec's own 'HOMES 24 → 36', so the bar drew 'HOMES 12→24' from the assumed base; it was the third wrong-baseline chip that night.
- Before blaming a count reader for a verdict, read the gate's tolerance, and calibrate readers on frames with known counts (`calib.py` → `reader-cal.json`; judge repeatability via `judgenoise.py` → `judge-noise.json`) before more renders. Why: a meta blamed Haiku's 4-vs-3 storey reads for three shadow parks, but `count_errors` allows ±1 on a changed count, so the stable task judge was the real decider; calibration (Fable full frame 9/10, Haiku 5/10) still changed which reader counts.
- Pin consequence figures to the thing they describe (a located park box gets a pin and leaders), not a bottom strip, and never put internal ids (plot codes) or unexplained abbreviations ('PROJ') on screen. Why: critics named all three; the strip placement cost the task vote even when layout and text won. A slider-type control (scrub, slider, dial) names its quantity and range ('SUN 9→15 H', 'DEC→JUN'); a bare 'TIME SCRUB' reads as an unexplained verb. Placed tiles have no range, so scope such rules by control kind. When a state's whole point is a spatial consequence (shadow reach, a setback, a walk radius), the code-drawn HUD draws that geometry on the map from the spec's numbers instead of only writing it: before dashed, after filled, labelled at the tips ('WAS 32 m' / 'NOW 16 m EST'). Scale it by a distance the spec already states (the building-to-park gap equals the park distance), so the drawing cannot disagree with the figures. Remove that figure from the strip so it appears once, and draw nothing when the anchor (e.g. a located park box) is missing. Fold the anchor's own figures (park clear-by, into-park, edge distance) into the drawing's two tip labels ('NOW 16 m · CLEARS PARK BY 4 m EST') rather than pinning them separately; give each tip a dot plus a leader to the label's near edge. Share the geometry function with the validator rule that checks the same crossing, so drawing and gate cannot diverge. When the new path subsumes an older test's path (park pins), keep that test on the old path by removing the input that triggers the new one, with a logged reason. Once the geometry is drawn, keep only the headline callout at the outline and move the second figure to the ticker; the tips already show it. Small code-drawn labels have their own text rules. Each tip names its quantity and carries EST ('SHADOW WAS 32 m … EST'), because a bare 'WAS 32 m' loses the text vote. Space arrows (' → ') in chips and discs drawn at 14 px or smaller: unspaced, the critic reads '48→24' as '48+24' and 'DEC→JUN' as 'DEC>JUN', even though vision confirms a real arrow. Wrap a disc label at the most balanced split, keeping the arrow group and a trailing unit with their number ('SUN / 09 → 15 H'). Draw the spaced form but keep the spec's text in the manifest, so matchers don't change. Why: three shadow rounds lost the task vote to 'the trade-off is asserted, not shown' while every figure in them was correct; drawing the shadow flipped task to the candidate on a 0-render replay, after which layout lost to four labels clustered on the lawn. Expect each fixed layer to expose the next one: replay after every HUD fix, and read the newly losing layer's issues before rendering again. After each reject, print `top_issue` for the candidate side (B in PC, A in CP) of every layer that picked the parent, in both orders. Fix what both orders name, then re-compose that round's cached scene (`hud.compose`, no render) and vision-check it before relaunching. Cap renders per state on a flat metric (a `BUDGET.json` read through `n_cand(state)`, e.g. 1 for a tying state), so each HUD iteration costs one render.
- When you rename a display string, route every matcher on it through one predicate (`hud.score_chip(c)`) and test that predicate against the producer's real output (`planspec.score(...)['display']`). Why: a `startswith('SCORE')` styling check silently dropped the chip highlight after the rename, and no test failed.
- Every rubric flag that constrains state order or conflicts (two states planning opposite changes to one building) needs a code site, usually the pool picker (`choose_pool`): grep for it before trusting the rubric line. Why: 'growth waits for shadow' existed only in the rubric, and the loop drew growth while shadow was open.
- Make every rubric/ordering rule executable before the next round: a rule that lives only in RUBRIC.md (e.g. 'the later state waits while an opposite plan on the same building is open') gets ignored by the pool chooser, and the loop spends a render on a state that should wait. Encode the rule in the chooser or validator with a red test from the round that broke it; a fail-closed pool-empty stop that results is intended, not a bug.
- The loop's catch-all round error must log the full traceback (a `round-errors.log`) and the innermost frame (`file:line func`) in the event, not only `repr(e)`. Why: the same `'NoneType' has no attribute 'group'` killed three rounds across two days with no frame, so it could never be root-caused. Grep `events.log` for a repeated round-error string before assuming it is new.
- The keep box deliberately includes the consequence geometry (cast shadow, lane change), so in states that draw that geometry it can cover most of the frame. Every outline-anchored callout slot then collides and the headline falls back to a corner, with a leader across another block. When geometry is drawn, anchor the headline at the geometry's origin, checking collisions against `used[1:]` (`used[0]` is the keep box). Record `fallback` on every callout, and assert `fallback is False` plus distance to the anchor in a test that uses the round's own keep box. The building face itself is still unknown from that box; locating it needs its own vision box.
- When one state ties round after round, tell the task critic the round's decision, give a first version an absolute accept rule, calibrate with a known-worse control in both orders, and pin receptors to what the parent picture shows. Recipes: [judging one decision per round](planning-specs.md#judging-one-decision-per-round). Why: the task critic never knew it was judging shadow, so it compared a shadow study against an accepted section screen and tied five times.
- At a chained exit, check that the child picture still shows the parent's decided countable (for example, the anchor cut to 3 storeys stays 3 in the growth round). Use the calibrated reader on a parent|child sheet plus a crop, because uncalibrated vision over-reads low buildings by +1. Why: nothing in the chain check compares the decision across links; r081 had to be checked by hand.
- In a UI cohesion pass (making many surfaces read as one product against a reference like omp), judge every round on a per-surface BEFORE | NOW contact sheet and ask the judge two separate questions: did cohesion improve, and did the surface lose content or its signature picture (a diagram, a chart, the seat ring)? Why: a judge asked only about cohesion scores a card that deleted its one diagram as a win, and the owner then sees a quieter but emptier product. Restyle the picture, never delete it. Recolouring an ornate renderer (a flag that mutes colours and drops serif) is not restraint either: the judge still reads glows, specular highlights, clipped labels and a foreign tile background as a pasted-in image. What passes is a flat redraw built from the card's own primitives: hairline strokes in border and text tokens, mono labels centred under each node so none can leave the square, a size cap (about 170 px), and no gradients. Re-shoot only the surfaces you changed (the sweep's `--only <surfaces>` flag) so each round costs minutes, not the full sweep. Do not edit any source while a capture is running. The sweep's source-drift guard aborts the run, and the round is lost. Batch your edits, then capture. Read-only work such as vitest and vision checks is fine during a capture. When a rewrite stops calling a renderer option, revert that option's edits in the renderer so no dead branch is left behind. Earlier rounds' tests can pin the old decision ("every svg ≤32 px" bans any picture). When you reverse that decision, rewrite those assertions to the new invariant: the picture exists, is under the cap, has every label, and uses no mineral colours or gradients. Never delete the assertions. If vision keeps reporting pills or boxes that your CSS doesn't draw, stop re-asking vision. Search the captured HTML's `<style>` blocks for every rule matching the element's classes, and check specificity and order. A global rule (such as a glass bubble on `.sf.sf-text`) ties with a scoped reset like `[data-agent-tree] .sf-text`, and because it is declared later it wins. Scope the reset at equal or higher specificity in the component (`[data-agent-tree] .sf.sf-text`), so the component renders the same in the harness and in every real mount.
- Calibrate a realism ("does it look real") reader on an untouched real object at the same camera before running look rounds against it. If the metric stays at 0/N through several rounds whatever changed, suspect the judge before the asset, because an uncalibrated question can be unreachable even for real photogrammetry.
